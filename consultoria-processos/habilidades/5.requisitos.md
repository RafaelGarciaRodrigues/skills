# Lista de requisitos

Com base no texto lido dentro de `WORK_DIR`\UNIFICADO que gerou o resumo, identifique todos os requisitos abordados:

- no mínimo 7 requisitos, sem limite de máximo
- ordenados por relevância decrescente
- titulo deve ser uma frase curta — são ações ou soluções solicitadas
- requisito não é um problema, necessidade ou dificuldade
- a descrição é uma explicação detalhada
- se necessário, inserir citações entre aspas do texto que originou o requisito
- relevância: inteiro de 0 a 100 (quantidade de texto que aborda o tema, importância declarada, ou necessidade de alta relevância atendida)
- identificação da origem:
  - `"CONTEXTO"` se o requisito foi tirado diretamente do texto dos arquivos
  - `"INSIGHT"` se é uma ideia acionável não discutida no texto

Para requisitos de tipo INSIGHT:
- crie no mínimo 3 insights
- ideias acionáveis não discutidas nos arquivos
- comporte-se como analista de estratégia: direto, sem elogio, sem coaching. Curtos, com porquê mínimo. Aponte riscos se houver. Nada genérico sem um "como"
- na descrição inclua uma referência bibliográfica relacionada ao insight

## Formato de saída

Responda APENAS com o JSON abaixo, sem nenhum texto antes ou depois, sem blocos de código markdown:

```
{"5.requisitos": [
  {
    "titulo": "Título do requisito",
    "relevancia": 95,
    "identificacao": "CONTEXTO",
    "descricao": "Descrição detalhada do requisito."
  },
  {
    "titulo": "Título de insight",
    "relevancia": 60,
    "identificacao": "INSIGHT",
    "descricao": "Descrição do insight. Referência: Autor, Ano, Obra."
  }
]}
```

Regras do JSON:
- A chave raiz é exatamente `"5.requisitos"`
- O valor é um array de objetos, cada um com: `titulo` (string), `relevancia` (inteiro 0-100), `identificacao` (`"CONTEXTO"` ou `"INSIGHT"`), `descricao` (string)
- Aspas dentro de strings devem ser escapadas com `\"`
- Quebras de linha dentro de strings devem usar `\n`
- O array deve estar ordenado por `relevancia` decrescente
